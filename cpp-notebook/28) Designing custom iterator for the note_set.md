## STL compliant implementation



### 1. The STL Requirements

For an iterator to be compatible with the Standard Library, it must provide:

- **Member Aliases**: Standard algorithms look for `value_type`, `difference_type`, `pointer`, `reference`, and `iterator_category`.
- - **Pointer/Reference Semantics**: It must behave like a pointer.
    
- **Comparison Operators**: `==` and `!=` are mandatory.

```cpp
class iterator 
{
public:
    // 1. Mandatory STL Traits
    using iterator_category = std::forward_iterator_tag;
    using value_type        = note;
    using difference_type   = std::ptrdiff_t;
    using pointer           = void;  // We don't return pointers to bits
    using reference         = note;  // We return by value (Proxy pattern)

    // 2. Constructors
    constexpr iterator() noexcept : bits_(nullptr), index_(12) {}
    constexpr iterator(const std::bitset<12>* bits, size_t index) noexcept 
        : bits_(bits), index_(index) 
    {
        advance();
    }

    // 3. Dereference
    [[nodiscard]] constexpr note operator*() const noexcept 
    { 
        return note{static_cast<uint8_t>(index_)}; 
    }

    // 4. Increment (The "STL Scan")
    constexpr iterator& operator++() noexcept 
    {
        ++index_;
        advance();
        return *this;
    }

    constexpr iterator operator++(int) noexcept 
    {
        iterator temp = *this;
        ++(*this);
        return temp;
    }

    // 5. Comparison
    [[nodiscard]] constexpr bool operator==(const iterator& other) const noexcept 
    { 
        return index_ == other.index_; 
    }
    
    [[nodiscard]] constexpr bool operator!=(const iterator& other) const noexcept 
    { 
        return !(*this == other); 
    }

private:
    void advance() noexcept 
    {
        while (index_ < 12 && bits_ && !bits_->test(index_)) 
        {
            ++index_;
        }
    }
    const std::bitset<12>* bits_;
    size_t index_;
};
```


### proxy iterator

A **Proxy Iterator** is an iterator that points to data that doesn't actually exist in memory in the form you're requesting it.

a proxy iterator "fabricates" or "simulates" the object on the fly when you dereference it.

```cpp
// Inside your iterator
[[nodiscard]] constexpr note operator*() const noexcept 
{ 
    // This is the Proxy action: creating a value on the fly
    return note{static_cast<uint8_t>(index_)}; 
}
```

## building the constructors

```cpp
class iterator

    // Points to the end of a set by default.
    constexpr iterator() noexcept 
        : bits_(nullptr), index_(12) {}

    // 2. Parametric Constructor
    // Used by begin() and end() to create a valid iterator.

    }
```

### comparison


		  constexpr bool operator==(const iterator& other) const noexcept = default;


When you use `= default`, the compiler performs what is called a **member-wise comparison**.

```cpp
// What = default actually does:
[[nodiscard]] constexpr bool operator==(const iterator& other) const noexcept 
{
    if (this->bits_ != other.bits_) return false;   // 1. Check the pointer
    if (this->index_ != other.index_) return false; // 2. Check the position
    return true;                                    // Both match
}
```

### proxy iterator and -> operator

for operator* we did this:

```cpp
 constexpr reference operator*() const noexcept
 {
  return note{ static_cast<uint8_t>(index_) };
 }

```

we cant do the same for operator->

why??

When you call `operator*`, you are creating a **temporary** `note` object on the stack.

```cpp
// DANGEROUS CODE - DO NOT DO THIS
note* operator->() {
    note temp = note{index_}; 
    return &temp; // ERROR! temp dies as soon as the function ends
}
```

The pointer you return would point to "garbage" memory because the `temp` note was destroyed the moment the function finished.


**`operator->`** is designed by the C++ language to return a **pointer** (or something that acts like one). It doesn't hand over a copy; it hands over a "map" to where the object lives.


```cpp
struct arrow_proxy {
    note n; // We store the temporary note safely here

    // This returns the address of the note stored INSIDE this proxy
    const note* operator->() const noexcept { 
        return &n; 
    }
};


// 2. The operator itself

[[nodiscard]] constexpr arrow_proxy operator->() const noexcept 
{ 
  return arrow_proxy{ **this }; // Create a note and wrap it in the proxy 
}


```


why ** this>?

- this -> pointer to the current object
*  * this is the current object itself
*    * * this -> calling the * opertor on the current object


**why no constructor needed for the arrow proxy?**

In C++, a `struct` (or class) with no private members, no virtual functions, and no user-defined constructors is considered an **Aggregate**.

You can initialize it using curly braces `{}` and the compiler will automatically map the values you provide to the member variables in order.

The compiler looks at `arrow_proxy` and says: _"I see this struct has one member variable (`note n`). The user gave me a `note` object. I will simply copy that note into the member `n`."_

if written manually:

```cpp
struct arrow_proxy {
    note n;
    
    // Manual constructor
    explicit constexpr arrow_proxy(note note_val) noexcept 
        : n(note_val) {}

    const note* operator->() const noexcept { return &n; }
};
```

In modern C++23 style, we usually stick with the aggregate (no constructor) for tiny "helper" structs like this. It’s idiomatic and efficient.
